## 一、项目概述

一款像素卡通风格的 2D 俯视角精灵对战 RPG 小游戏，核心玩法参考经典宝可梦式循环：

**探索地图 → 遭遇野生精灵 → 战斗 / 捕捉 → 治疗与养成 → 商店补给 → 继续探索**

### 1.1 功能清单（对应需求编号）

| # | 功能 | 简述 |
|---|------|------|
| 1 | 精灵对战 | 回合制战斗：技能、属性克制、伤害数字（圆圈内数字样式） |
| 2 | 精灵捕捉 | 战斗中使用精灵球捕捉野生精灵，加入背包/队伍 |
| 3 | 精灵治疗 | 局内（道具治疗）+ 局外（精灵中心/治疗点） |
| 4 | 精灵背包与道具背包 | 双背包：队伍精灵管理 + 道具栏（精灵球、药水等） |
| 5 | 商店系统 | 金币买卖道具 |
| 6 | 地图与探索 | 瓦片地图行走、草丛随机遇敌、多区域 |
| 7 | 人物移动 | 四方向行走（需求 7 与 10 重复，合并实现） |
| 8 | 初始 8 只精灵 | 见 §四 精灵设计 |
| 9 | 存档功能 | JSON 存档，随时保存/读档 |

### 1.2 技术约束（Pyxel 特性决定）

- 窗口默认 256×256（可设，如 240×180），调色板 16 色，像素风格天然契合。
- 资源统一用 Pyxel Resource Editor 制作 `.pyxres`（图块、精灵图、音效），或用 PNG + `pyxel.images` 加载。
- 中文文本：Pyxel 默认字体不支持中文，需参考示例 `13_custom_font.py` 加载 BDF/TTF 字体（素材目录已有 `PixelMplus12-Regular.ttf`、`umplus_j12r.bdf` 可直接用）。
- 地图：可用 Tiled 编辑器 + `.tmx`（参考 `15_tiled_map_file.py`，素材含 `urban_rpg.tmx/png`）。

## 三、核心系统设计

### 3.1 精灵数据模型（model/creature.py）

```
精灵实例 = {
  species_id: int,      # 种族编号 1-8
  name: str,            # 名字（可改昵称，可选）
  type: str,            # 火/水/草/风/光/暗/雷
  level: int, exp: int,
  hp_max: int, hp: int,
  mp_max: int, mp: int,          # 蓝量：释放技能消耗
  attack: int, defense: int, speed: int,
  skills: [skill_id ×≤4],
  status: None/中毒/麻痹…（MVP 可先不做异常状态）
}
```

种族数据（基础值 + 升级成长）放在 `species_data.py`，升级用简单公式：`属性 = 基础值 + 等级 × 成长值`。MP 同样随等级成长。

### 3.1.1 蓝量（MP）规则

- **每个技能有 MP 消耗**（skill_data.py 中配置，如：撞击 0、火花 4、烈焰 10、治愈波动 8）。
- **MP 不足时技能置灰不可选**；普攻类技能（撞击）消耗 0，保证永远有招可用。
- **恢复方式**：战斗外治疗点同时回满 HP 与 MP；道具"蓝药水"恢复 MP；战斗胜利/升级时可恢复少量 MP（升级回满）。
- **UI**：战斗中每只精灵显示**血条（红/绿渐变）+ 蓝条（蓝色）**双条，数值以"当前/最大"文字标注；蓝条宽度约为血条的 2/3，置于血条下方。

### 3.2 战斗系统（battle/ + battle_scene.py）

- 回合制，速度决定出手顺序。
- 玩家指令四选一：**战斗（选技能）/ 精灵球捕捉 / 道具 / 逃跑**。
- 伤害公式（MVP）：`伤害 = max(1, (攻击方atk - 防御方def/2) × 技能威力系数 × 克制系数) + 随机浮动±10%`。
- 属性克制表（初版）：

| 攻击\防御 | 火 | 水 | 草 | 风 | 光 | 暗 | 雷 |
|---|---|---|---|---|---|---|---|
| 火 | 1 | 0.5 | 2 | 1 | 1 | 1 | 1 |
| 水 | 2 | 1 | 0.5 | 1 | 1 | 1 | 1 |
| 草 | 0.5 | 2 | 1 | 1 | 1 | 1 | 1 |
| 风 | 1 | 1 | 2 | 1 | 1 | 1 | 0.5 |
| 光 | 1 | 1 | 1 | 1 | 0.5 | 2 | 1 |
| 暗 | 1 | 1 | 1 | 1 | 2 | 0.5 | 1 |
| 雷 | 1 | 2 | 1 | 0.5 | 1 | 1 | 1 |

- **伤害数字动画（需求 8 的特殊要求）**：受击位置飘出"圆圈内数字"样式的伤害值，上移渐隐。实现：`ui/damage_number.py` 用 `pyxel.circ` 画圆 + 内置小字体画数字（参考 `03_draw_api.py`）。
- 战斗演出：精灵轻微震动/闪烁表示受击（参考 `99_flip_animation.py`、`16_transform.py`）。

### 3.3 捕捉系统（catch_calc.py）

- 捕捉率：`a = (1 - HP当前/HP最大×0.7) × 精灵球倍率 × 种族捕捉难度系数`，随机数判定。
- 成功 → 加入队伍（队伍上限 6，超出进仓库）；失败 → 敌方行动。

### 3.4 背包系统（model/bag.py）

- **道具背包**：`{item_id: 数量}`，战斗中可用（药水/精灵球），地图菜单中可用药水。
- **精灵背包**：队伍（≤6）+ 仓库（列表），支持查看能力、调换顺序、与仓库交换。

### 3.5 治疗系统

- **局内**：道具（伤药/好伤药）在战斗或菜单中使用。
- **局外**：地图上的"治疗点"（精灵中心 NPC/治疗祭坛），对话后全队 HP 全恢复，播治疗音效与闪光动画。

### 3.6 商店系统（shop_scene.py）

- 与商店 NPC 对话进入：买入列表（显示价格、持有金币）、卖出道具（半价）。
- 初版商品：精灵球、伤药、好伤药、复活草（可选）。

### 3.7 地图与探索（field_scene.py + map_data.py）

- 瓦片地图：16×16 图块，地图用 Tiled 编辑为 `.tmx` 或直接二维数组定义（MVP 建议二维数组，简单可控；后续可换 tmx，参考官方示例 15）。
- 地图元素：可行走地块、障碍（树/水）、草丛（随机遇敌，约 10%/步）、NPC（商店/治疗/对话）、出入口（切换地图区域）。
- 初版规划 2~3 个区域：新手村（商店+治疗点）→ 野外草丛 → 洞窟/高等级区。
- 遇敌：进入草丛每步掷随机，按区域遇敌表随机生成野生精灵（等级范围浮动）。

### 3.8 人物移动（需求 7/10 合并）

- 四方向网格移动，按住方向键连续走格（每格 8~12 帧插值动画），碰撞检测障碍。
- 朝向 4 方向帧切换，走路 2 帧循环动画。

### 3.9 存档系统（save_io.py）

- JSON 存档：玩家位置/地图、金币、队伍与仓库精灵全部字段、道具背包、游戏时间。
- 触发：菜单内"存档"选项；标题画面"继续游戏"读档。
- 预留 3 个存档位（MVP 先做 1 个）。

## 九、美术执行方案（已选定方案 D：程序化像素绘制）

> 决策过程：原方案 B（AI 生图 + 手工修）经评估演进为方案 D。**可行性结论：可行，且比 B 更优**。Pyxel 的 16 色调色板 + `pyxel.pix(x, y, col)` 逐点绘色天然适合"数据即美术"的路线——精灵图就是一张调色板号的二维表，全部由 DSH 以代码形式编写、随时调整重画，跳过图片文件与 .pyxres 编辑器的来回。

### 9.1 技术路线（核心设计）

**不直接每帧调 `pyxel.pix()`**（每帧数千次调用有性能浪费），而是采用"**像素矩阵数据 → 启动时烘焙到 Image 对象 → 运行时 `pyxel.blt()` 贴图**"：

```
src/assets_gen/
├── palette.py        # 调色板常量：如 C_FUR=9(橙)、C_MANE=8(红)、透明=None
├── sprite_base.py    # SpriteMatrix 基类：字符画→索引表→pyxel.image 烘焙器
└── sprites/
    ├── fire_lion.py      # 小火狮 32×32 + 16×16 图标
    ├── water_drop.py     # 水滴滴
    ├── grass_rabbit.py   # 兔小子
    ├── wind_griffin.py   # 小狮鹫
    ├── light_unicorn.py  # 独角兽
    ├── dark_cerberus.py  # 三头犬
    ├── phoenix.py        # 不死鸟
    ├── thunder_kid.py    # 闪电小子
    ├── player.py         # 主角 4 方向 × 2 帧
    └── tileset.py        # 地图图块（草/草丛/树/水/路/房/洞窟）
```

**字符画定义方式**（以小火狮示意，每个字符 = 一个调色板号）：

```python
# sprites/fire_lion.py
PALETTE = {".": None, "K": 0, "O": 9, "R": 8, "Y": 10, "W": 7}  # K描边 O毛色 R鬃毛 Y高光 W白
ROWS = [
    "................................",
    "....KKKKKKK.....................",
    "...KOOOORRRKK...................",
    "...KOOORRRRRRK..................",
    # ... 共 32 行
]
```

烘焙器读取字符画 → `img.pset(x, y, col)` 写入 `pyxel.image(32, 32)` → 存入全局图库字典 → 游戏内 `pyxel.blt(x, y, img, 0, 0, 32, 32, colkey=0)` 绘制。启动一次烘焙全部素材，帧循环零解析开销。

**相比 AI 生图路线的优势**：

| 维度 | 方案 D（程序化） | 方案 B（AI 生图） |
|---|---|---|
| 修改成本 | 改一行字符画立即生效 | 重新生成 + 减色 + 导入 |
| 风格一致性 | 共用调色板常量，天然统一 | 每张需人工减色校正 |
| 调色板合规 | 只能是 16 色内，不会越界 | AI 图必然超色，需后处理 |
| 迭代预览 | 改完直接跑游戏看效果 | 需外部工具链 |
| 风险 | 字符画画复杂造型考验构图功力 | 生成质量不稳定 |

### 9.2 素材清单与规格

| 类别 | 数量 | 规格 | 绘制方式 |
|---|---|---|---|
| 精灵战斗图 | 8 只 | 32×32 | 字符画矩阵 |
| 精灵地图图标 | 8 只 | 16×16 | 独立简化字符画（非程序缩小，保证辨识度） |
| 主角行走图 | 4 方向 × 2 帧 = 8 张 | 16×16 | 字符画矩阵 |
| 地图图块集 | 约 12~16 种 | 16×16 | 字符画矩阵 + 部分程序化纹理（如草地噪点用循环+伪随机撒点生成） |
| UI 元素 | 血条/蓝条框、对话框、光标、精灵球 | 8×8 / 16×16 | 直接 `pyxel.rect/rectb/circ` 程序化绘制，无需素材 |
| 伤害数字 | 圆圈+数字 | — | `pyxel.circ/circb` + 字体绘制（程序化） |

### 9.3 制作流程（每只精灵 / 每批素材）

1. DSH 编写字符画初稿 → 运行游戏内"素材预览模式"（专门场景平铺展示全部素材）→ 截图给用户确认。
2. 不满意则改字符画（改局部只需几行），重跑即见效果，快速迭代。
3. 确认后定稿，进入下一只。

### 9.4 风格统一要求

- 全部素材只用 Pyxel 默认 16 色；每只精灵主色 + 深色描边（1px）+ 1~2 个高光色。
- 描边统一用色 0（黑）或与主色同族的深色；8 只精灵体量感接近（主体占画面 60~75%）。
- 调色板常量集中在 `palette.py`，全局唯一配色来源。
