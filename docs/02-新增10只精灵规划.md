## 一、目标与边界

### 1.1 目标

新增 **10 只精灵，编号接续 9–18**，扩充为 **18 只精灵**，重点补足当前 roster 的空缺：

- 现有 8 只属性分布：火 2、水 1、草 1、风 1、光 1、暗 1、雷 1；
- 新增后：火 3、水 3、草 3、风 2、光 2、暗 2、雷 3，共 18 只；
- 新增的不是“数值更大的旧精灵”，而是现有精灵没有的**定位**：高速火系、水盾、水系治疗、草系刺客、草系重装、风系辅助、暗系法系、光系医护、雷系均衡、雷系慢速爆发。

### 1.2 硬性边界（本批不做）

| 项 | 决定 | 原因 |
|---|---|---|
| 新属性 | **不新增**（只使用火/水/草/风/光/暗/雷 + 内部“无”） | 避免改克制表与全部旧数值 |
| 双属性 | **不做** | 现有公式与 UI 都是单属性 |
| 进化 | **不做** | 现有系统明确不支持，ID 与图鉴也不会留进化链 |
| 异常状态（中毒/麻痹等） | **不做** | 现状明确排除，不因扩精灵重新打开 |
| 新技能效果类型 | **只允许 damage / heal / debuff_atk** | 复用 `battle_scene._apply_attack` 现有三分支 |
| 携带道具、天气、先制、合击 | **不做** | 与本批目标无关 |
| 新地图 | **不做**，只向现有 3 张图加刷怪点/权重 | 地图数据与碰撞已有稳定结构 |
| 存档版本 | **`save_version` 保持 1** | 只增加可引用的 species_id，旧字段结构不变 |
| 直接使用资源包图片 | **不使用** | 见 §二；全部由模型手绘 |

## 二、素材使用规则（图片仅作参考，模型手绘）

### 2.1 铁律

1. **不复制、不裁切、不缩放、不描图、不自动量化、不调色**资源包内任何 PNG。
2. 不把原图放进 `assets/`、`docs/` 或 `src/assets_gen/`；仓库不新增任何第三方像素数据。
3. 不搬用 Tuxemon 的英文名、中文译名、种族值、技能名、技能数值；本文件的数值全部按本项目公式重新设计。
4. 资源包图片只用于确定**题材关键词**（例如“狐狸 + 火 + 烟雾”“圆形水兽 + 水花”“植物忍者”），最终造型由模型用字符画重新构图。
5. 画出的图不得以“改色/翻转/局部拼接”方式还原参考图的轮廓；验收时以**同屏并排看不出逐像素对应**为准。

### 2.2 为什么这样定

资源包 README 写的是“直接复制图或代码 → 项目需 GPL-3.0 并署名”，但**项目当前是 MIT**，且 10 个候选中多数在原署名文件里并没有逐条条目。直接用图会把许可证问题变复杂。改为原创重绘后：

- 游戏代码与自绘素材仍按项目当前 **MIT** 分发；
- 参考图仅存在于本地参考目录，**不随游戏分发**；
- 若未来确实要用原图，必须逐张确认作者与许可证（CC-BY-SA 4.0 / CC BY / GPL 等不同），更新 `NOTICE`，并**单独评估**是否触发传染性条款——不能把“整个素材包”当成一个统一许可证。

> 这不是法律意见。涉及公开发布或商业发布时，建议让用户自行确认许可；本方案通过“不使用原图”把风险降到最低。

### 2.4 每只精灵的绘制规格

| 项 | 规格 |
|---|---|
| 战斗图 | **32×32**，字符画 `list[str]`，字符→调色板索引，透明 `.` |
| 地图图标 | **16×16**，独立构图，不是战斗图缩小 |
| 动态帧 | **已确认**：首版交付**静态 1 帧**并通过验收，之后追加 **2 帧**呼吸/尾巴摆动；仍沿用 `creature_{id}_battle` / `_icon` 命名，动画帧作为独立素材名（如 `creature_{id}_battle_1`）后续接入 |
| 描边 | 统一色 **5 DARK_PURPLE**，图中**不得出现色 0**（`colkey=0` 会镂空） |
| 主色 | 属性主色取 `palette.TYPE_COLORS`；高光用色 7 / 10 / 15，暗部用同族深色 |
| 眼睛 | 白色眼白 + 色 1 瞳孔 + 白高光；不得用色 5 画瞳孔 |
| 构图 | 主体占画布 60%–75%，留 2px 透明边；正/侧 3/4 视角统一 |

## 四、逐只精灵设计

> 通用：等级上限 20，成长公式 `floor(基础 + (等级-1)×成长)`，不做 STAB，不做异常状态。
> 技能栏最多 4 个，学习点沿用 **Lv1 / Lv8 / Lv16**（2 + 1 + 1）。

### 4.1 雾尾狐（ID 9｜火｜高速游击）

**外观（手绘规格）**
- 32×32：低伏的小狐狸，尾巴占右侧 1/3，尾巴末端由橙→黄渐变成烟团；耳朵大而尖，前爪离地呈起跑姿态。
- 不画大面积烟雾遮脸；烟只做轮廓外缘的 2–3 个圆，保证 32px 下能认出狐狸。

### 9.4 现有关键约束：野生精灵只带 Lv1 技能（**本批不修复，已确认**）

核对代码发现：`field_scene` 生成野生精灵时是 `Creature(species_id, level)`，**没有传 `skills`**；而 `Creature.__init__` 在 `skills is None` 时只取 `learnset.get(1)`。结果是：

- 洞窟 15 级的不死鸟，只有「烈焰 / 再生」，没有 Lv8、Lv16 技能；
- 新精灵如果按 §8 以 8–16 级出现在野外或洞窟，同样只会用 Lv1 的两招；
- 捕捉回来的高等级精灵，之后升到 16 级只会学 Lv16 那一招，**永远补不回 Lv8 技能**。

**用户已决定：不在本批修复，保持现状。** 因此：

| 影响 | 说明 |
|---|---|
| 高等级野生新精灵 | 只会 Lv1 两招，威胁低于其纸面数值 |
| 捕捉入队后 | Lv8 技能永久缺失，只有 Lv16 会补 |

| 规划处理 | 保留本节作为已知缺陷记录；未来若要修，按下方方案 B 执行 |

> 将来若决定修复，方案 B 为：新增 `learnset_up_to(species_id, level)` 按等级累积技能（最多 4 个），在 `field_scene` 生成野生精灵时传入；同时补 `tests/test_species_data.py` 与 `tests/test_wild_encounter.py` 断言。该修复会同时加强旧野生精灵，需重新试玩洞窟难度。

## 十一、平衡目标与风险

### 11.1 设计目标

| 目标 | 判定 |
|---|---|
| 属性克制关系 | **完全沿用现有 7 属性表**，不为新精灵新增或削弱克制 | 风、雷在当前表中本来就没有 2× 弱点（旧版既存），本批不借扩精灵之机改动 |
| 新精灵不出现“六边形战士” | 是；速度、攻击、耐久三者必须至少牺牲一项 |
| 没有新精灵同时拥有“最快 + 最高攻 + 最高 HP” | 是；雾尾狐快但脆，荆星芽攻高但慢，涟漪豚厚但慢 |
| 最强单发仍是不死鸟 130 | 是（新最高 125） |
| 最高 MP 不超过 55 | 是（绒医团/雷云团 55，高于旧的 54） |
| 捕捉系数不高于 0.55、不低于 0.25 | 是（0.25 仅剩荆星芽、雷云团；灯火鳅已放宽到 0.40） |
| 所有新精灵 20 级 HP ≤ 110 | 是（涟漪豚 110 为上限） |

### 11.2 已知风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 涟漪豚 HP 110 + 高防过肉 | 战斗拖长 | 其 ATK 26、SPD 19，输出极低；可先用降攻/换人处理 |
| 荆星芽 115 草系重击 + 吼叫 | 对水属性压制强（草克水 2×） | 草被风 2× 克制，且它慢，留给风系先手 |
| 灯火鳅/绒医团双治疗 | 消耗战 | 治疗都是**自愈**，不能奶队友，节奏不会无限拖 |
| 雷云团 125 单发 | 秒残血 | SPD 23 出手晚，且 17MP 只能放 3 次（Lv20 MP55） |
| 新增 10 只稀释遇敌 | 旧精灵难遇 | §8 权重保留旧精灵合计 68%（野外）/67%（洞窟） |
| 野生精灵只带 Lv1 技能（旧实现） | 高级新精灵实战威胁低于纸面；捕获后缺 Lv8 技能 | **已确认不修**（§9.4）；接受该缺陷，不因此调整新精灵数值 |
| 风 / 雷无 2× 弱点（旧表） | 新精灵难以被属性针对 | 本批不改表；用低耐久/低速度/高消耗限制强度 |
| 测试硬编码导致 CI 红 | 无法交付 | §10.2 已列全，实施时先改测试再跑 |
